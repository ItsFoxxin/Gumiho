# GUMIHO 0.8.2 — Smooth melee, shields, and mace compatibility

Minecraft Java 1.21.1 / NeoForge 21.1.248 / Java 21. Client-only; not a cross-version JAR.
This incorporates the work initially discussed as 0.8.1. There is no separate 0.8.1 release here.

## Install and test

Close Minecraft, keep the previous JAR outside the profile's mods folder, and install only
`gumiho-neoforge-0.8.2.jar`. Back up `config/gumiho.json` before testing. No live CurseForge
files are changed by the build. Existing toggles, allowlists, player lists, and layouts remain intact.
Auto Shield starts OFF and is not automatically enabled by an existing preset.

Use Left Shift → Combat. Click Combat Options (or right-click a combat card), then page 4.
Test single-player or an allowlisted server; mark consenting PvP test partners as Enemy.
End disables protected automation. Manual attacks are still vanilla; release the attack button
when testing Cooldown Attack or Mace Smash Timing.

## Smoother melee aim

Aim is now updated every rendered frame, interpolating the target's position. A capped
exponential approach softens the final turn instead of moving in fixed 20 Hz steps.
The speed setting retains its old scale: 3 degrees/tick means a maximum of 60 degrees/second.
New Aim Ease defaults to 120 ms (50–400 ms); a larger value eases more gently near the target.
Long/stalled frames are capped so resuming cannot produce a large catch-up turn.

A competing target must win four consecutive tick samples before replacing a valid target.
Invalid targets clear immediately; eligible pinned enemies bypass this delay. Normal line of
sight, target filters, FOV, and range remain enforced. The camera visibly rotates; this does not
provide silent rotations or extra reach. At high fall speeds, aim still needs time to turn:
look toward the intended landing target before descending.

## Auto Shield

- Equip a shield in the OFFHAND, then enable Auto Shield. It never equips a shield, replaces a
  totem, changes slots, or turns you toward a threat.
- Nearby frontal hostile mobs and eligible armed/swinging enemy players can trigger blocking.
  Default range is 4.5m (2–6m). Threat detection is a heuristic, not knowledge of enemy inputs.
- Optional projectile checking looks for loaded incoming arrows/tridents on a short predicted
  path toward you. It is not a complete ballistic simulation. It excludes your own projectiles
  and projectiles whose known living owner is excluded by combat filters.
- Default hold is 12 ticks (6–30), with a four-tick release window. Vanilla shield activation
  delay, durability, disabling, cooldown, angle, and server validation still apply. No invulnerability.
- Allow Attack Windows defaults ON: release for a fully charged eligible automatic attack.
  Incoming projectiles take priority over ordinary grounded strikes.
- Manual use takes priority. The module restores physical use-key state when releasing its
  own synthetic hold, including a rebound use key. It does not take over bows or food.
- Auto Eat gets priority when hungry and hotbar food is available. Auto Totem can replace the
  offhand shield; Auto Shield stops rather than replacing it back.
- Shield input is released on disable, disallowed server, menu, focus loss, death, or world change.
- A held wind charge, or an airborne mace with Mace Smash Timing enabled, suspends shielding.
  This flight rule applies even if Allow Attack Windows is OFF, so it cannot block a mace sequence.

## Mace and wind-charge behavior

Melee Aim aims only. Cooldown Attack performs ordinary fully charged crosshair hits, including
grounded mace hits. Enabling Mace Smash Timing takes ownership of mace attacks: it waits for
descent, the configured minimum fall, vanilla smash eligibility, full charge, and a valid ray hit.
It will NOT perform grounded mace attacks in that mode.

The compatibility fixes are:

- Use the native `MaceItem.canSmashAttack` check as well as the configured descent/minimum-fall
  condition. Ascents, apexes, and elytra gliding do not trigger automated smashes.
- Recast from the player's current eye position at attack time, rather than depending on a
  previous rendered frame's crosshair result. Blocks and other pickable entities obstruct the ray;
  an enemy behind a teammate is not selected through that teammate.
- Respect vanilla item-change cooldown resets instead of resetting again when the weapon first
  encounters a target. An equipment snapshot still rejects automatic swaps made after the native
  player tick, preventing food/weapon swaps from using an old item's charge.
- Keep the shared full-charge and same-tick attack gate. A native mace needs a long recharge;
  switching to it very late in a short fall can still leave too little time to attack.
- Auto Weapon retains a held mace. Auto Eat will not begin while holding a wind charge or during
  an airborne Mace Smash Timing sequence. Melee automation does not attack with a held wind charge.

Wind-charge throws, jumps, mace selection, and landing/clutch decisions remain manual. The mod
does not rewrite fall distance, motion, damage, enchantments, or movement packets. Density, Breach,
Wind Burst, knockback, and successful-smash fall handling run through the game's normal attack path.
The existing Mace Status bonus remains UNENCHANTED fall bonus, not final damage or a safe-landing promise.

Vanilla distinctions, checked against the local 1.21.1 NeoForge game sources and the
[official Java 1.21 release notes](https://feedback.minecraft.net/hc/en-us/articles/27547857163917-Minecraft-Java-Edition-1-21-Tricky-Trials):

- A successful ordinary smash grants vanilla fall protection; a missed/blocked/rejected attack
  must not be treated as confirmation that you are safe.
- Wind-charge launch protection is relative to the launch/impact height, not universal immunity
  when landing farther below it.
- Wind Burst launches you again and removes the successful smash's fall protection. Chaining
  another smash or arranging a safe landing remains necessary.
- Client readiness is not a server acknowledgment. Latency, modded combat rules, and fast movement
  may cause missed hits; no client-only code can guarantee a successful landing.

## Verification

Automated checks: `gradlew.bat build` runs `combatRegression`. The standalone suite can also run
with `scripts/test-combat.ps1 -JavaHome C:\path\to\jdk21`. Coverage includes FPS-independent aim,
speed caps/no overshoot, stalled frames, target-switch hysteresis, pin/invalid-target behavior,
shield hold/release/attack windows, equipment snapshots, native-charge simulations, mace
thresholds/descent/relaunch cases, filters, and config preservation/normalization.

These are unit/build checks and source-level compatibility review, NOT an in-game physics or
network test. Live playtesting of your exact shader/Connector/FFAPI modpack is still pending.
