# GUMIHO 0.8.0 — Targeting and melee test build

Target: Minecraft Java 1.21.1 / NeoForge 21.1.248 / Java 21. This is not a cross-version JAR.
Ranged expansion is reserved for 0.8.5; movement for 0.8.9; HUD/utility for 0.9.0.

## Quick start

1. Close Minecraft and keep your old GUMIHO JAR outside the mods folder for rollback.
2. Install only gumiho-neoforge-0.8.0.jar in the client profile, not the dedicated server.
3. Open GUMIHO with Left Shift. Select Combat.
4. Click Combat Options in the sidebar, or right-click a Combat card.
5. Test against a hostile mob first. For players, use the player list to explicitly mark a consenting test player as Enemy.
6. Enable one new module at a time. All new automation defaults OFF and remains off in the existing presets.
7. Release left mouse while testing automatic attacks; vanilla manual clicks can still swing independently.
8. Press End to stop protected automation. Test single-player or an allowlisted server.

## What each module does

| Module | Behavior | Default | Allowlist |
|---|---|---|---|
| Melee Aim | Visibly turns your view toward the selected eligible target while you hold a sword, axe, or mace; does not attack | OFF | Required |
| Auto Weapon | Selects a hotbar sword for ordinary melee, or an axe against a shield facing you; retains a manually selected mace | OFF | Required |
| Cooldown Attack | Attacks the eligible entity under the crosshair at full charge, within normal interaction reach | Existing setting | Required |
| Mace Smash Timing | Attacks the eligible crosshair target while falling with a charged mace and the configured minimum fall distance | OFF | Required |
| Mace Status | Shows fall distance, readiness, and the unenchanted base smash bonus in HP damage units | ON, only shown with mace | No |
| Target / Intel HUD | Shared target selection, health, distance, shield, equipment, armor summary, threat, and hurt-animation time | ON | No |

When Mace Smash Timing is enabled, it owns mace attacks; Cooldown Attack does not also swing the mace on the ground. Both producers use the same charge and same-tick gate. Manual attacks are never canceled.

Auto Weapon only searches the hotbar. It does not reach into inventory, restore the original slot, or automatically select a mace. Within its preferred category it ranks base attack-damage modifiers, not enchantment matchups or final damage. A ten-tick swap debounce prevents rapid switching as a shield is raised/lowered.

Melee Aim runs whenever enabled and holding a supported weapon, without holding left mouse. It changes normal visible view rotation; it does not perform silent rotations, reach extension, or through-wall attacks.

## Combat Options

Page 1 — Targets:
- Hostile mobs: ON
- Marked enemy players: ON
- Passive/non-hostile mobs: OFF (enabling this can include animals and pets)
- Invisible targets: OFF; enabling still requires normal line-of-sight
- Priority: Crosshair, Distance, or Low Health
- Pinned eligible enemies take priority; pins cannot bypass filters, reach, or line-of-sight.
- Teammates, neutral players, creative/spectator players, armor stands, dead entities, and yourself remain excluded.

Page 2 — Limits:
- Target range: 4–96m, default 64m
- Full FOV: 10–360 degrees, default 120 (half on either side of the view direction)
- Melee range: 1–6m, default 3m; always capped by the player's normal interaction range and target range
- Melee aim speed: 0.5–10 degrees per tick, default 3
- Minimum mace fall: 1.6–12m, default 1.6
- Existing bow modules retain their own smaller range/angle limits as well as the shared filters.

Page 3 — Melee / HUD:
- Weapons Only: ON; only sword/axe/mace may auto-attack unless you opt out
- Wait Hurt Animation: OFF; when enabled waits for the observed hurt animation to clear
- Avoid Raised Shield: ON; skips frontal shield attacks unless using an axe
- Detailed Target HUD: ON for old Enemy Intel users, compact for target-only setups

Settings apply immediately in memory and save on Done/Escape.

## Estimates and limitations

- The mace number is the unenchanted fall bonus, not total hit damage. It excludes Density/Breach, armor, protection, resistance, critical modifiers, and server-specific changes.
- Smash readiness does not guarantee a target is in range or that a hit will succeed. No automatic jumping, wind-charge use, landing prediction, or fall-damage cancellation is included in 0.8.0.
- Hurt time shows the observed animation in ticks, not an authoritative server invulnerability timer. Optional waiting may reduce attack frequency.
- Shield state and threat are client-observed hints; the server decides whether an attack is blocked or disables a shield.
- The Target / Intel panel shows the selected target; automatic strikes still require the entity to be physically under your crosshair.
- The independent player tracker/directional indicators remain unchanged for the later awareness cleanup.
- No totem-pop counter, critical-hit automation, spear support, or new ranged trajectory system is included in this milestone.
- 1.21.1 mace mechanics reference: https://www.minecraft.net/en-us/article/mace . The piecewise base bonus and fall threshold were also checked against the local 1.21.1 mapped MaceItem bytecode.

## Upgrade / rollback

On the first load of an existing pre-0.8.0 config, GUMIHO creates an adjacent gumiho.pre-0.8.0.json backup without overwriting an existing backup. Enemy Intel is retired and merged into target_hud. If Enemy Intel was enabled, the new panel retains its position and detailed view. Other module settings, player groups, allowlist entries, and profiles are preserved.

No live CurseForge files are modified by the build process. If your customized layout overlaps a new panel, move it in HUD Editor. Reset Layout is optional and replaces your saved layout with defaults.

To roll back, close Minecraft, remove 0.8.0, reinstall 0.7.2, and restore the backup config if you want the two original target panels.

## Automated checks

Run the pure policy suite without Minecraft:
```powershell
.\scripts\test-combat.ps1 -JavaHome 'C:\path\to\jdk21'
```

The Gradle check task also includes combatRegression. Tests cover target-kind permissions, 100% charge, duplicate producers, reconnect identity, simulated sword/axe/mace recharge cycles, smash thresholds and base bonus boundaries, config migration, preservation, and invalid values.

Current build validation: the full NeoForge Gradle build passed, including 157 regression assertions. These checks do not replace in-game/network/render testing; the checklist below has not been executed in a live client.
