# GUMIHO 0.8.4 — Melee closeout

Minecraft Java 1.21.1 / NeoForge 21.1.248 / Java 21. Client-only, not cross-version.
Close Minecraft, back up config/gumiho.json, preserve the previous JAR outside mods, and
install only gumiho-neoforge-0.8.4.jar. No live CurseForge files are changed by this build.

## Mace Combo Lock

Enable the new Combat toggle Mace Combo Lock (OFF by default). It works independently of
ordinary Melee Aim, and takes over aiming when holding a mace so the two cannot fight.
Enable Mace Smash Timing separately if you want automatic charged strikes as well.

Acquire a visible eligible target while holding the mace and looking toward it. Initial
selection follows the usual target filters, priority, and acquisition FOV. The same target
is retained while ascending and descending, instead of being discarded outside melee reach.
Once locked, tracking does not require the target to stay inside the acquisition FOV.

Combat Options page 4 → Mace Lock Range defaults to 32m (6–64m), capped by global Target Range.
This is AIMING distance only. Attack raycasts, normal interaction reach, fall requirements,
full charge, and teammate/neutral exclusions are unchanged. The Target / Intel HUD reports
the actual retained target and shows MACE LOCK. Aim Speed and Aim Ease still control rotation;
yaw is held stable directly overhead to avoid flipping where horizontal bearing is undefined.

A newly selected eligible pinned enemy can override the current lock. Death, invalid target
group, leaving tracking range, loss of sight, weapon changes, menus, item use, focus loss,
disabled automation, or unauthorized server clears the lock. Eligible targets can be acquired
again when the conditions become valid. Switch away from the mace or disable the module to
release it deliberately. While holding a mace on the ground, the enabled module still aims.

Wind Burst supplies the bounce; this toggle does not generate jumps, strafing inputs, wind
charges, or guaranteed landings. It tracks the target rather than predicting a landing path.
You still control movement. Short bounces may end before the mace fully recharges; no attack
cooldown bypass was added. See 0.8.2/0.8.3 notes for native fall-protection and offhand-charge caveats.

## Impact-timed Auto Shield

The proactive archer detector and idle nearby-enemy holding are removed. Default behavior is:

1. Predict whether an already-loaded frontal arrow/trident intersects your near-future position.
2. Raise only when impact is within Shield Lead, default seven ticks (about 350 ms at 20 TPS).
3. Hold through the estimated impact plus one tick, then release if no new impact is predicted.

The local 1.21.1 LivingEntity.isBlocking implementation requires five ticks of shield use.
Therefore activation at the exact damage instant would be too late. Shield Lead is adjustable
from 5–12 ticks; higher values trade more movement slowdown for preparation time. Close-range
shots and latency can still defeat a reactive shield. This is prediction, not access to future
server damage. It cannot guarantee that every hit is blocked.

Prediction includes short gravity/drag stepping and conservative horizontal movement, rejects
stationary embedded arrows, tests block occlusion along trajectory segments, and ignores
Piercing arrows/no-physics return projectiles. No archer merely holding a bow triggers it.
The shield is directional: facing away, shield cooldown/disabling, unexpected movement, and
server/modpack rules can still cause damage. Sustained genuine arrow volleys can keep it raised.

Pressing the physical Use key ends only the module-owned shield use, preserves the real key
state, and yields to vanilla block placement/item use. Manual blocking is never canceled when
the module did not initiate it. Building/manual use takes priority even if that means accepting
an incoming hit. Releasing Use allows reactive defense again. Auto Eat's ongoing use is not
canceled. The existing wind-charge/mace-flight priority remains.

React to Swings is optional and OFF by default. It gives one brief six-tick defensive pulse
for a newly observed, nearby, facing eligible enemy swing. Merely standing near a mob does not
trigger it. Observed melee animation may arrive with/after server damage, so this option cannot
reliably pre-block instant melee attacks. Keep it OFF for projectile-only defense and maximum
freedom between arrows.

Old Melee Shield Hold and Allow Attack Windows controls are retired from the UI. Their saved
config fields remain for rollback compatibility but no longer drive shielding. The old
ShieldCycle implementation is replaced by ImpactGuard; old source archives remain available.

## Focused acceptance tests (live tests pending)

- Enable Mace Combo Lock + Mace Smash Timing; aim at a hostile mob or marked consenting enemy.
  Confirm MACE LOCK in Target HUD, then test Wind Burst ascent/descent with another target nearby.
  It should retain the original target and never attack from extended tracking distance.
- Compare Melee Aim ON vs OFF while Combo Lock is ON: only the combo controller should rotate
  a held mace. A sword should still use ordinary Melee Aim when enabled.
- Test target death, wall occlusion, target changed to teammate, range exit, weapon switch,
  End, alt-tab, and reconnect. Confirm no stale target persists across invalid conditions.
- With Auto Shield ON, stand near a non-attacking archer/enemy. Shield should stay down.
- Face normal incoming arrows at a moderate distance. Shield should rise shortly before
  projected impact and drop afterward. Compare Shield Lead 7 and 10 on your server.
- Place blocks manually while the module owns a block. The automatic block should end, then
  vanilla Use/building should work. Release Use and confirm defense can resume.
- Keep React to Swings OFF first; optionally enable it and test a fresh enemy swing vs an
  idle enemy. Record late blocks separately from idle holding.
- Retest manual shield, eating, offhand totem replacement, wind-charge swap, emergency stop,
  menus, death, disconnect/reconnect, and disallowed servers with the actual modpack.

Verification: full Gradle build and 7,331 regression assertions passed. Tests cover retained
combo identity, pin override/clear behavior, impact lead boundaries, bounded hold expiration,
invalid predictions, manual-reset state, optional swing pulses, existing charge safeguards,
aim math, swaps, and config validation. They do not simulate real network physics or prove a
block percentage / successful bounce chain. Those live checks above remain pending.
