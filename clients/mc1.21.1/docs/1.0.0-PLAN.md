# GUMIHO 1.0.0 plan

Status: 0.9.5-link.3 member-management client/relay candidate implemented; live game acceptance remains pending.
See [candidate setup and tests](0.9.5-link.3.md).
Maintain separate Minecraft 1.21.1 and 26.2 NeoForge artifacts throughout.

## Release sequence

1. Preserve the accepted 0.9.2 baseline. Elytras, fishing and crystal PvP are explicitly deferred until after 1.0.
2. Link development: approved separate relay (local-only development first), protocol/relay/companion implementation,
   automated privacy tests, then two-client end-to-end tests.
3. 0.9.5: finalize settings and UI including Link; fix the user's live-test findings.
4. 0.9.9: feature freeze, clean-profile/install/upgrade/rollback tests, modpack and multiplayer checks.
5. 1.0.0: release only after the required acceptance gates pass.

Do not label 1.0 complete just because both JARs compile. No release dates are promised.

## Current base scope

Existing combat/ranged awareness and opt-in automation; version-specific native spears on
26.2 only; existing Bridge/Tower/Wall and movement; visual/utility HUDs;
named kit setups; portable HUD positions and sizes; emergency disable.
Keep the user's accepted 0.9.2 layout and feature set; no new elytra, fishing or crystal modules.

The movement base does not include autopilot, flight-speed modification, automatic rockets,
no-fall, automatic equipment swapping or new inventory automation.

## Link v1 - separate relay approved, implementation in progress

Minecraft installation remains client-only. The user approved a separate small self-hosted
relay for private cross-network team updates, NOT a Minecraft server mod/plugin. Initially build/test
locally without deploying, opening firewall ports, or changing the game server.

The relay is a service with real hosting/security requirements. A purely local client UI
cannot deliver teammates' remote updates without some agreed communication mechanism.

- Separate Link-only companion for teammates, without GUMIHO combat/movement automation.
  Full GUMIHO integrates the same protocol. No dependency on everyone installing the cheat client.
- Hold-to-view panel (rebindable), not another permanently crowded HUD.
  Team tab: member-approved Link data and pings. Nearby tab (full GUMIHO only):
  local loaded-player information from the existing tracker, never broadcast to Link.
  Proposed optional mini-tracker defaults OFF; preserve users' existing tracker toggle
  until the replacement panel is usable. Link-only clients have no enemy/combat tracker.
- Maximum ten members, private invitations, revocation/removal and independent teams.
- Roles: Founder, Co-founder, Inner Circle, Officer, Member; least-privilege membership management.
  Relay promotion permissions are implemented; final review and native administration UI are still pending.
- Member-owned visibility: choose which roles may receive location; default no location sharing.
  Co-founder/Inner Circle access must be an explicit sender choice, not an unavoidable backdoor.
- Separately opt-in health/hunger/basic equipment status. No full inventory manager in v1.
- Manual pings (location, regroup/help/danger), shared only with the intended team,
  with short expiry, bounded count/rate, dimension/server separation and a clear sender.
  Sending a location ping reveals that point even if continuous location sharing is off.
- Connection, stale/offline and sharing indicators. Disconnect or revoke sharing clears
  cached live data; recipients cannot be made to forget information they already saw.
- No automatic enemy information, remote module control, remote commands, telemetry service,
  invisible entitlement locks, or public discovery of teams.

## Proposed security and deployment requirements

- Invite-based authentication, per-member credentials, authorization at the relay,
  server-enforced team separation and role-filtered response data.
- Per-client consent before connecting or transmitting status/location; no auto-upload.
- Separate private Link config. Kit/HUD exports must never include tokens or sharing settings.
- HTTPS for non-loopback service endpoints, bounded messages/timeouts, rate limiting,
  background networking, reconnect backoff and offline-safe gameplay.
- No shared master/admin credential distributed to ordinary members.
- Plain HTTPS protects transit but does not hide data from the relay operator. Do not call
  the service end-to-end encrypted without actually implementing and verifying that design.
- Host, domain, access method, persistence/backups and certificate ownership must be agreed
  before deployment. No existing Fox Den service is presumed to be the chosen host.

## Required acceptance gates

- Both native mod builds and Link-only companions build and contain the right metadata/classes.
- Core combat, movement, preset, input and layout regressions pass.
- Two authenticated clients exchange only the sender-approved data; test every role pairing.
- Another team and revoked members receive no private updates. Role downgrade/share-off,
  disconnect, stale snapshots and server/dimension changes clear live visibility correctly.
- A teammate installing Link-only receives no combat/aim/placement automation classes.
- No network work blocks the render/game thread; no background service is required when Link is off.
- Test native start/stop/override behavior, shaders/rendering, menus/resizing and key collisions.
- Verify fresh install, upgrade preserving permissions/presets, config restart and rollback.
- Document known limits, operations/backup steps and the exact supported version matrix.

## Deferred beyond v1

Explicit user decision: Elytra Takeoff, Flight Status and expanded flight controls,
fishing features, and crystal PvP are post-1.0 work. Existing elytra development sources
are preserved separately and must not be copied into the 1.0 candidate.
The combined 0.9.5-preview.1 elytra build was compiled but not distributed as a release.

Also deferred unless separately approved:

Full shared inventory management, map history, persistent tracking, external dashboards,
automatic tactical analysis, accounts/public hosting, monetization/unlock systems, and expanded
flight/navigation automation. Avoid turning Link into another full cheat distribution.
