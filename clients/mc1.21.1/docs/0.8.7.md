# 0.8.7 - mace resets, expanded defense, held previews

Minecraft 1.21.1 / NeoForge 21.1.248 / Java 21. Client-only test release.
Replace the previous JAR; keep the old JAR and a copy of config/gumiho.json outside
the mods folder for rollback. The existing module IDs/settings are preserved.

## Diagnosis from the recordings and code

Sampled frames from both supplied recordings show repeated incoming damage and
mace tracking of distant zombies while nearer mobs surround the player. The old
ComboLock retained any still-visible target inside its broad tracking radius;
neither landing feasibility nor the start of another bounce made it reconsider.
That permanent-lock implementation has been removed, not left alongside the new one.

Auto Shield did not require Auto Melee/Cooldown Attack. Its optional melee swing
reaction was OFF by default and used offensive eligibility filters. A received
swing animation is also not a reliable advance warning: vanilla shield blocking
starts only after five ticks of use. This update addresses those limitations;
it does not promise to block every hit or override server damage rules.

## Mace Combo Assist | 철퇴 연속 보조

The former Mace Combo Lock keeps its saved ID/toggle, but now:

- Reacquires at takeoff, landing and an observed descent-to-upward bounce.
- On the ground (or unsupported flight modes), only selects within normal melee reach.
- In normal air, scores the projected landing offset rather than retaining a distant
  visible target indefinitely. Late descents have a tighter correction envelope.
- Rejects unreachable lateral candidates; a much better reset opportunity can replace
  the old target immediately, while small score changes use target stability filtering.
- Existing teammate/neutral exclusions, target eligibility, visibility, pin priority
  among reachable targets, charge timing and actual melee reach remain in place.

Enable Combat > Mace Combo Assist. Mace Smash Timing is still the separate toggle
that performs descending attacks; the combo assistant itself does not attack.
Ground melee automation remains a separate choice.

Combat Options, page **5/5**:

- **Landing Guide ON:** orange ring = estimated feet landing; green ring = predicted
  target location; connecting line = the remaining correction. Rings are depth-tested.
- **Mace Air Correction OFF:** opt in to small ordinary forward/strafe inputs toward
  the target landing. Your movement, jump and crouch inputs always take priority.
  This never teleports, changes velocity directly, creates a jump or extends reach.
- **Reset Radius 4m:** maximum correction envelope, adjustable 1-8m. The effective
  envelope shrinks when there is little flight time left; increasing it isn't a
  promise that every selected target can be reached.

Mace Status adds landing time and FORWARD/BACK/LEFT/RIGHT/ALIGNED guidance.
Creative flight, elytra, riding, fluids, Levitation and Slow Falling do not use the
normal-air correction model. Test actual resets in survival, not creative flight.
The estimate uses a center-foot trace and current motion: player width, future input,
other collisions and server corrections can change the landing. It is not fall protection.

## Auto Shield: independent defense

You need Auto Shield enabled, a usable offhand shield, and an authorized server
(or allowed single-player world). You do NOT need auto-melee or an attack target.

- **Close Melee Guard ON (page 5):** proactively guards against a visible, facing,
  nearby player/hostile or aggressive mob. It is independent of offensive friend,
  enemy and target-category filters: defending against a teammate is not attacking one.
- **Explosion Guard ON (page 5):** estimates nearby lit TNT/creeper fuse windows;
  charged creepers use a larger proximity envelope.
- **Shield Projectiles (page 4):** arrows/non-piercing tridents, blaze/ghast fireballs,
  wither skulls, crossbow fireworks and approximate near-term shulker bullet threats.
  Homing bullets use their current heading, not a guaranteed future homing path.
- **React to Swings (page 4):** still available for an additional short reaction pulse.

Guarding only helps toward the current front-facing arc. It does not rotate you
toward attackers. Close attackers can keep the shield up; turn Close Melee Guard
OFF if you prefer projectile-only timing and freer movement. Physical Use/building
still takes priority and releases only the module's own block.

Shields cannot cover all damage. Piercing, bypass-shield damage, potion effects,
damage over time, falls, rear hits, instant explosions with no visible fuse, axe
disable windows and hits arriving before the five-tick startup are not guaranteed
defenses. Explosion predictions are not blast/damage guarantees. Defense still
pauses for item use, wind-charge launch grace and airborne mace-smash actions so
it does not interrupt those actions. No invulnerability or server exploit is added.

## Held projectile previews

Enable Utility > Projectile Paths. Right-click it, go to page **3/3**, and leave
**Held Preview ON**. This flag is independent of My Projectiles/Other Projectiles,
which filter projectiles already in flight.

- Bow: preview follows current draw power after the minimum launch threshold.
- Crossbow: shows the projected loaded shot while loading or holding a loaded bow.
  Loaded vanilla Multishot shows up to three paths, subject to Max Paths.
- Trident: preview while charging; it still needs ten ticks to actually throw.
  Riptide does not show a misleading thrown-trident path.
- Wind charge, pearl, snowball, egg, splash/lingering potion and XP bottle: preview
  while holding the item, before the instant-use action.
- Crossbow fireworks: pink straight flight preview and in-flight tracking. Fuse
  expiry/blast radius is NOT predicted; a displayed contact might be beyond fuse expiry.

Main/offhand selection follows active use, otherwise the supported mainhand item
takes priority. No ammo/cooldown restrictions are bypassed and nothing auto-fires.
Holding a drinkable potion, loose firework, fire charge, fishing rod or Eye of Ender
does not produce a fabricated ballistic preview. Homing/mod-specific mechanics,
elytra fireworks and modded weapons require their own models.

Held previews share the path count, range, horizon and simulation budget; they get
priority over in-flight paths. Colors indicate projectile type, not team. Other
players and mob shots remain visible using Other Projectiles. Predictions omit
random spread, unknown server changes and future entity decisions.

## Focused test checklist

Use a disposable survival arena before your actual war server:

1. With all melee/aim automation OFF, enable only Auto Shield. Face a zombie with
   an offhand shield and Close Melee Guard ON; verify blocking independently.
   Back out of reach or turn Close Melee Guard OFF and verify release. Test manual
   block placement/eating handoff. Test with a neutral player as the attacker too.
2. Face a skeleton at moderate range, then test tridents, blaze/ghast fireballs and
   lit TNT/creepers with sufficient health/protection. Record misses; do not assume
   an already-raised shield proves that an attack was actually blocked.
3. Enable Mace Combo Assist and Mace Smash Timing. Walk among targets: the lock
   must not stay on one 10m away. Jump/wind-charge into a descent, then test Wind
   Burst chains: a new bounce should reevaluate the landing opportunity.
4. Observe orange/green rings and directional HUD text. Start with Air Correction
   OFF, then enable it and release movement keys. Verify mild correction; press
   a movement key/crouch to confirm immediate manual priority. Test missed hits
   with a safe landing area: this feature must not be treated as fall immunity.
5. Draw a bow without releasing: the trajectory should appear and lengthen with
   charge. Repeat crossbow loading/loaded Multishot, charging trident, and each
   instant throwable. Riptide and drinkable potions should not show false paths.
6. Turn Held Preview OFF: only in-flight paths remain. Turn both in-flight owner
   filters OFF with Held Preview ON: your held preview should still work.
7. Check F1, menus, dimension/world changes, GUI scaling, emergency disable and
   the exact Iris/Sodium/Connector combination. Verify no stale markers or movement.

## Verification boundary

Automated tests cover reset lifecycle, feasible target scoring, steering direction,
launch math, defensive filters, guard expiry, config bounds and existing regressions.
The obsolete permanent-lock test was replaced by reset/reacquisition tests.
Build/archive verification checks the 0.8.7 metadata and removal of the old class.
These checks and reviewing the old recordings do not replace live validation of
0.8.7 hit timing, block rates, landing accuracy, shader rendering or FPS.
