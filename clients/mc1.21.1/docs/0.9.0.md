# 0.9.0 - UI / Visual / Utility test release

Status: paired 1.21.1 and 26.2 test release. Builds and pure regression checks pass;
new rendering hooks and UI changes still require in-game acceptance.
The packaged 0.8.9 JARs/source archives remain unchanged for ongoing user combat tests.

## Implemented in this pass

- Network HUD distinguishes Local, Offline, unknown latency and server-reported ping;
  FPS is separate. This is an indicator, not a network optimizer. Samples every ten
  player ticks rather than querying player information each rendered frame.
- HUD panels outside the current GUI viewport are displayed inside it. Preferred saved
  positions are retained, so increasing the viewport restores them. This is recovery,
  not automatic collision avoidance; overlapping panels can still be dragged in the editor.
- Combat Options sits at the bottom of the sidebar, visible only in Combat.
- The main menu footer uses two rows when four full labels cannot fit. Module pagination
  reserves the actual footer height. Setups opens saved kits/layouts; built-in profiles
  remain available inside its Kit tab.
- Players screen uses viewport-relative panel/button widths and a bottom-anchored Done
  button. Its list clips/scrolls above the footer; draft player names survive resizing.
- Combat section selector cycles All, Melee, Mace, Ranged, Spears (26.2 only), Defense,
  Awareness. Unsupported/empty groups are skipped. This is UI organization: existing
  module IDs, toggles and behavior are not replaced or duplicated.
- Long module descriptions scroll horizontally while hovering over their text area,
  pausing at both ends. Text stays clipped away from toggle buttons.
- Combat Options pages reorganized as Targets, Aim/Range, Melee/HUD, Mace, Shield.
  Existing values and limits preserved.
- Every one of the 25 Combat Options controls has short English/Korean hover help,
  including target Priority. Help distinguishes estimated guidance from native reach,
  shield startup and server-controlled damage.

## Visual/Utility additions and fixes

- NEW Visual > Compass HUD: cardinal/intercardinal direction plus bearing with north = 0°.
- NEW Utility > Equipment Durability: exact remaining/max and percentage for damageable
  armor and held tools, colored warning at 25% or less. No auto-equipping or repairing.
  Both new modules default OFF and are independently draggable.
- Combat Resources includes wind charges. One inventory pass per player tick replaces
  repeated per-frame scans; cached, bounded text panels keep numbers readable.
- Effects sort soonest-expiring first, put permanent effects last, display infinity
  correctly, and show a +more count beyond the three visible effects. Timers reserve
  their width; translated names are fitted by pixels rather than character count.
- Item Cooldowns shows Ready or percent LEFT, not attack charge or shield startup.
- Fullbright renamed Max Brightness, retaining the saved fullbright ID. It uses vanilla
  gamma maximum (not night vision) and restores the previous/manual brightness on disable.
- No Weather renamed Hide Precipitation, retaining no_weather ID. Client-only render
  hooks suppress vanilla rain/snow, splashes and ambient rain sounds WITHOUT changing
  rain/thunder values. Sky darkness, lightning, thunder sounds and weather gameplay stay
  native. Current weather immediately renders again when disabled.
- Survival Alerts clears cached hit-direction information on player/world changes and
  disable; text fitting now respects the font width.
- Mace Status now uses its full three-line height for both the background and orange
  accent. The other HUD accent strips were checked for the same stale-height problem.
- Default utility panel spacing accounts for taller panels. Saved custom positions are
  preserved, so use HUD Editor to adjust old overlapping positions, or choose Reset Layout.
  Resizing recovers off-screen panels but does not promise automatic collision avoidance.

## Requested building extension

Right-click Movement > Bridge Assist to open **Building**. Select one mode; the module
still defaults OFF and only runs in allowed single-player/server sessions.

- **Bridge:** held mainhand blocks fill beneath your movement at edges, with automatic
  crouch. Manual Use/Attack takes priority.
- **Tower:** hold blocks and your normal Jump key. Places beneath your feet only while
  ascending and after your body clears the destination. Uses normal jumps: no flight,
  automatic jumps or vertical-velocity modification.
- **Wall:** hold blocks + Use and aim at a block face. Repeats normal placement upward
  or sideways as you move your aim; releasing Use stops it. It does not select enemies
  or automatically build a cage. Switch to another item or disable it for normal Use.
- **Place Delay:** 4/6/8/12 ticks between attempts; rejected attempts are throttled too.
  Native reach, visible support, world border/build height and entity occupancy are checked.
  Server protection/placement rejection still applies. No inventory refill or block swapping.
- Menus, lost focus, death, item use, Attack input and loss of server authorization stop
  placement. A forced crouch is released without releasing physically held crouch.
  Wall mode owns block Use input to avoid duplicate vanilla/automation placement.

This is the requested Bridge Assist extension, not the full future movement/elytra pass.

## Named kits and portable HUD layouts

Open **Setups | 설정 모음** from the main-menu footer, or **Saved | 저장** in the HUD Editor.

- Select **Kit**, enter a name such as Bow kit or Mace, and click **Save New**.
  This snapshots current GUMIHO options, module toggles, and HUD positions.
- Select **HUD Layout** for position-only saves. Toggle states and other settings are
  NOT included. Built-in combat profiles are available only in the Kit tab.
- **Previous/Next** browses saved names for the selected type. **Load** asks for confirmation.
- To transfer between versions: **Copy HUD** in one client, then **Paste HUD** in the
  other and confirm. You can paste the copied JSON into a text file/message temporarily.
  Both clients must support this new 0.9.0 format; it is not imported by 0.8.9.
- Files live in the instance's `config/gumiho-setups/kit/` and `config/gumiho-setups/hud/`.
  Copy named JSON files into the same subfolder of another instance to transfer kits/layouts.
  Identical names are never overwritten; save revisions under new names.
- Every load/import first saves a **Before-...** Kit snapshot. Load that file from the
  Kit tab to restore the preceding settings/layout. If backup creation fails, loading stops.
- Exports/imports exclude server allowlists, single-player authorization, player groups,
  pinned players and active built-in profile. Minecraft Controls/keybinds, shader settings
  and other mods' settings are not included.
- Kit loading releases existing automation first and rechecks the destination server
  policy. Disallowed automation is skipped, not force-enabled. Unknown version-specific
  settings are ignored; unsupported HUD IDs are retained as data but not rendered.
- Layout uses Minecraft GUI coordinates, not physical screen pixels. Matching GUI scales
  gives the closest placement; smaller viewports clamp panels into view. No layout scaling
  or automatic overlap avoidance is promised.

HUD modules use the shared HUD Editor. No separate popup is added where there are no
individual settings. Equipment is a detailed local display; Survival Alerts remains a
compact urgent warning, not a second full equipment panel. No teammate data sharing,
inventory automation, wall tracking, new combat automation or Link service is added.

## In-game checks

1. Keep your previous JAR and a config copy; install only the matching new version.
2. Try large and small GUI scales. Check Combat Options, Players > Done, two-row footer,
   section cycling, full hover descriptions and all combat-control tooltips.
3. Toggle Compass and rotate: north 0°, east 90°, south 180°, west 270°.
4. Equip/damage armor and tools; confirm Equipment numbers and the low-durability color.
   Swap inventory items, including wind charges: Resource counts should update promptly.
5. Apply finite and infinite effects. Check minute boundaries, infinity, expiry ordering,
   translated names and +more count; remove effects and check contextual hiding.
6. Use a pearl / have a shield disabled: confirm the cooldown decreases to Ready.
   The shield panel is not a timer for raising the shield.
7. During rain/snow, toggle Hide Precipitation on and off. Change the weather while it
   is enabled, then disable: it must show CURRENT weather, not an old snapshot.
   Check gameplay weather and thunder remain unchanged. Repeat with your shader/modpack.
8. Change vanilla brightness, enable/disable Max Brightness, and verify restoration.
9. Test Network in single-player versus multiplayer. Resize, drag and restart; custom
   positions should persist. Reconnect/change dimension: no stale hit-direction alert.

10. Right-click Bridge Assist and test all three modes with ordinary full blocks.
    Bridge across a small gap, hold Jump to tower, then hold Use and aim along faces to
    build a wall. Release Use/Jump and confirm placement stops. Try occupied cells,
    out-of-reach supports and server-protected blocks: no bypass or packet spam.
    Open menus, switch items, hold Attack, disable the module and leave an allowed
    server; verify placement/crouch ownership stops. Also test with Auto Shield enabled.
11. Hold a mace and check all three status lines: orange strip and background should
    cover the complete panel, including Combo Assist. Repeat at multiple GUI scales.

12. Save two differently configured kits. Change options/toggles/layout, then load each.
    Confirm Cancel changes nothing, Save New refuses an existing name, and Before-...
    restores your previous setup. Try a load on a non-allowlisted server: no bypass.
13. Copy HUD between the paired clients. Confirm positions transfer but toggles, combat
    options, permissions and player lists do not. Test malformed clipboard JSON and a
    missing name: show an error without applying anything. Restart and check persistence.

## Technical notes

Minecraft version. Config registration follows [NeoForge's mixin configuration format](https://docs.neoforged.net/docs/gettingstarted/modfiles/).

compilation and display-math tests alone do not certify them.
