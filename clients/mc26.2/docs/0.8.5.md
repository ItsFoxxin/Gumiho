# 0.8.5 - first ranged baseline

Minecraft 1.21.1 / NeoForge 21.1.248 / Java 21. Client-side only.
This starts the ranged milestone; it does not complete the entire ranged review or
implement the separate newer-Minecraft port. Existing 0.8.4 melee, mace, shield,
friend protections and active-automation server allowlisting remain unchanged.

## Projectile Paths | 투사체 궤적

Open GUMIHO (Left Shift by default), select Utility, and enable Projectile Paths.
It defaults OFF. Right-click its card to open its own two-page settings screen.
This is informational rendering, not aim assistance or automatic throwing.

The module predicts the flight of supported projectiles already in the world:

| Projectile | Color / model |
| --- | --- |
| Normal and spectral arrows | Gold; drag and gravity |
| Outbound tridents | Cyan; gravity and trident water drag |
| Ghast, blaze and dragon fireballs | Orange; directional acceleration and drag |
| Wither skulls | Orange, or pink for dangerous skulls; separate drag |
| Player and breeze wind charges | Pale cyan; constant-speed vanilla flight |
| Splash/lingering potions | Purple; potion gravity |
| Pearls, snowballs and eggs | Green; throwable gravity |
| XP bottles | Lime; stronger gravity |

Predicted block contact gets a small cross in the path color; entity contact gets
a red cross. Paths stop at the first estimated contact, even if a projectile might
pierce, bounce, be deflected, or continue after that contact. A marker is NOT a
guarantee of damage, explosion radius or a safe landing.

## Settings

- Range: 16-128m, default 64m. Bounds both discovery and prediction around you.
- Prediction: 10-80 ticks, default 40 (roughly two seconds at 20 TPS).
- Max Paths: 1-24, default 12. Nearest supported visible projectiles get priority.
- My Projectiles / Other Projectiles: independent filters, both default ON.
  Unknown owners count as Other; these filters do not infer friend/enemy teams.
- Impact Markers: default ON. Disable to retain only the path lines.

Calculations are cached per client tick instead of rerun per rendered frame.
There is a hard 1,200 simulation-step budget per tick across all paths. High counts,
crowded entity scenes, and long horizons can still cost frame time: reduce Max
Paths and Prediction first. No measured FPS improvement is claimed.
Rendering reuses a private buffer, hides with F1, uses camera-relative coordinates,
and depth-tests against the world. It does not deliberately draw through terrain.

## Scope and limitations

- In-flight paths only: holding an unthrown item does not display a preview yet.
- Unsupported: homing shulker bullets, returning Loyalty tridents, fireworks,
  fishing hooks, and unknown modded projectile types. They need dedicated models.
- Estimates use current client positions and vanilla 1.21.1 flight profiles.
  Moving targets, owner collision immunity, water boundaries, lag, portals,
  deflection and server/mod changes can make the actual result different.
- Only loaded chunks are inspected; prediction stops at bounds/unloaded space.
  A path that ends because of range, time or budget has NO impact cross.
- Projectiles initially hidden behind terrain are not selected. A selected path
  remains subject to normal depth testing; this is not an ESP/X-ray feature.
- No changes to bow targeting, release timing, crossbows, spear support, or Link
  are included in this first 0.8.5 build.

## Focused in-game checks

Back up your config and keep the 0.8.4 JAR outside the mods folder for rollback.
Install only one GUMIHO JAR. Test in a disposable creative world first.

1. Confirm the menu and brand HUD say 0.8.5 and previous settings survived.
2. Enable Utility > Projectile Paths. Shoot an arrow toward a wall: check a gold
   curve and a contact cross; the path disappears after the arrow embeds.
3. Repeat with a thrown trident, potion, XP bottle, pearl, snowball and egg.
   Use a non-Loyalty trident first; returning Loyalty flight should be excluded.
4. Spawn a ghast in a safe arena and provoke a shot. Check the orange path; also
   test a blaze and wind charges. Do not mistake the cross for blast radius.
5. Shoot through water and across a water boundary. Note differences from air;
   boundary predictions are estimates and may shift as the shot enters water.
6. Toggle My Projectiles and Other Projectiles independently using a second
   player or a skeleton. Turn both off: no paths should remain after the next tick.
7. Disable Impact Markers: curves remain, crosses disappear. Shorten Prediction
   or Range: a truncated curve must not display a false impact cross.
8. Check F1, module off/on, world exit/re-entry, and changing dimensions: no
   stale lines from another world. Restart to check setting persistence.
9. Compare vanilla graphics and your exact Iris/Sodium/Connector shader setup.
   Verify paths are visible in front of terrain, hidden behind it, and do not
   affect other outlines, clouds, GUI text, or translucent blocks.
10. Recheck melee full-charge timing, reactive shield release, mace combo lock
    and wind-charge-to-mace swapping from 0.8.4; no behavior change is intended.

## Verification boundary

Automated tests cover the pure integration math and config bounds, together with
the existing combat regression suite. The Gradle build checks NeoForge linkage.
These checks do not establish live collision accuracy, shader compatibility or
in-game performance; the focused world tests above remain required.
