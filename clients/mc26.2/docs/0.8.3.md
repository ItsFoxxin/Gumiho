# GUMIHO 0.8.3

Minecraft 1.21.1, NeoForge 21.1.248, Java 21. Client-only. Install only the new JAR;
preserve 0.8.2 outside the mods folder and back up config/gumiho.json for rollback.

## Aim

The standard melee turn cap increases from 60 to 120 degrees/second. Easing changes from
120 to 80 ms, still using frame-time-independent smoothing and four-tick challenger stability.
Existing values exactly matching the previous defaults upgrade once (config schema 2).
Other customized values stay unchanged. Adjust Combat Options page 2 → Melee Aim Speed,
and page 4 → Aim Ease. Suggested starting values are 6 degrees/tick and 80 ms.
Increasing speed does not remove the soft finish or extend targeting range.

## Shields

The old 12-tick hold/four-tick gap applied even during incoming arrows, repeatedly exposing
you and restarting vanilla shield activation. Projectile defense now overrides that cycle,
including ordinary attack requests, and holds eight ticks after the last threat sample.
The renamed Melee Shield Hold setting only governs the ordinary melee cycle.

Projectile checking now examines loaded arrows/tridents up to 32 blocks away, simulates
18 ticks of gravity/drag, and allows a small margin for your horizontal movement. Visible
eligible archers facing you within 24 blocks can trigger preemptive blocking before release.
This can intentionally hold a shield longer against an archer even if they have not fired yet.
Incoming arrows from neutral players, friends, or dispensers can trigger defense too; this
does not change the filters that protect those players from automated attacks.

Keep Shield Projectiles ON. Face the shooter: this module still does not rotate your view to
block attacks behind you. Close-range surprise arrows, latency, shield cooldown/disabling,
and Piercing crossbow arrows can still defeat blocking. This is not a guaranteed interception
system. Gravity/water/player-motion prediction is approximate, not a server simulation.
Manual item use is preserved. New eating attempts yield while the projectile guard owns the
shield; ongoing/manual eating is not forcibly canceled. Mace-flight/launch priority remains.

## Wind Charge → Mace

New Combat toggle, OFF by default and server-allowlisted:

1. Put a wind charge in your selected mainhand slot and a mace somewhere in the hotbar.
2. Enable Wind Charge → Mace. Aim at the ground and throw the charge manually.
3. At the next client tick/render opportunity after local use starts the charge cooldown,
   select the first mace in hotbar order and send the normal selected-slot update.
4. No inventory mace means no swap. A failed/canceled use without cooldown, changed slot,
   expired attempt, death, disconnect, disabled module, menu, or disallowed server cancels it.
5. The last charge in a stack is supported. Offhand throws do not cause a swap.

This is local-use confirmation, not a server acceptance acknowledgment. It does not swap
before the throw packet or wait for the projectile to hit the ground. A short launch grace
keeps Auto Eat/Auto Shield from interrupting while server knockback is arriving.

The unmodified mace's 0.6 attack speed means about 1.67 seconds of full recharge (roughly
34 ticks for our conservative full-charge gate). A quick swap saves manual input time;
it cannot make a short wind-charge jump long enough to fully recharge. Custom server
attributes or lag can change practical timing. Mace Smash Timing still requires full charge.

Alternative: keep the mace in your MAINHAND and wind charges in your OFFHAND. Throw from
the offhand to avoid changing your mainhand weapon and resetting charge. This trades away
the offhand shield/totem; Auto Totem may replace the charges when its health threshold triggers.
The swap toggle can stay off for this setup. Native fall protection and Wind Burst caveats
from the [0.8.2 guide](0.8.2.md) still apply; no automatic throwing/jumping/clutch or cooldown bypass.

The cooldown and input sequencing were checked against local 1.21.1 Player, MaceItem,
WindChargeItem, and MultiPlayerGameMode sources. The
[official Java 1.21 notes](https://feedback.minecraft.net/hc/en-us/articles/27547857163917-Minecraft-Java-Edition-1-21-Tricky-Trials)
describe wind-charge launch and fall behavior.

## Focused live tests (pending)

- Compare Melee Aim at the old 3/120 settings and new 6/80 settings, then compare 30/60/144 FPS.
  Expect a faster turn without overshoot or target-switch flicker.
- With only Auto Shield enabled and an offhand shield, face a skeleton at 12–20 blocks.
  Expect sustained blocking through shots, not periodic drops. Repeat with an enemy archer,
  a neutral test player, and a dispenser. Repeat with ordinary melee attacks enabled.
- Record 20 frontal normal-arrow shots and how many blocked. Keep distance, armor, server,
  and facing consistent with the 0.8.2 comparison. Test rear/Piercing shots separately.
- Enable Wind Charge → Mace. Test multiple charges, the last charge, no mace, multiple maces,
  a manual slot change, and an offhand throw. Expect one swap per accepted mainhand throw.
- Compare mainhand charge → auto-swap against mainhand mace + offhand charges. Watch the
  attack cooldown HUD; no partial-charge auto-hit should be allowed by the swap.
- End emergency stop, menus, alt-tab, death, reconnect, and an unauthorized address must not
  leave held shield input or a pending swap behind. Verify with your actual modpack and latency.

Build and regression checks are automated; an improved in-game arrow-block rate has NOT yet
been measured. Unit coverage includes aim math, target stability, sustained projectile guard,
grace expiration, gap override, one-shot throw triggers, cancellations, cooldowns, and migrations.
