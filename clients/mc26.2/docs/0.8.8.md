# 0.8.8 - shield attack windows

Minecraft 1.21.1 / NeoForge 21.1.248 / Java 21. Client-only test release.
Keep the previous JAR and a copy of config/gumiho.json outside the mods folder for
rollback. Install only one GUMIHO JAR. This release does not migrate your server,
world, CurseForge profile or modpack to 26.2.

## What changed

Close Melee Guard could renew defense continuously in a crowd. The attack modules
correctly refused to attack while using an item, but there was no handoff between
them. Vanilla also discards attack clicks in its using-item branch. The existing
shieldAttackWindows setting was present in the config but had no implementation.

Enable **Shield Attack Windows** in **Combat Options > page 3/5**. It defaults ON
but does not enable Auto Shield or any attacking module by itself. Saved OFF
values are preserved.

- **Manual attack:** a fresh press of your remapped Attack key releases our block
  before native attack processing. Vanilla handles the click, including mining;
  this does not synthesize a hit. The short opening gives your input priority over
  automatic attacks. Holding the button is not a stream of new presses.
- **Automatic attack:** with Cooldown Attack enabled (or an eligible Mace Smash
  action), a window opens only for a valid crosshair target, full attack charge,
  unchanged equipment, normal reach/visibility and the existing target protections.
  Weapons Only, Wait Hurt Animation and Avoid Raised Shield remain enforced.
- **Reblock:** after one automatic hit, defense reevaluates next client tick.
  If the target disappears or the hit is cancelled, the opening expires after two
  ticks. A re-raised shield gets five startup ticks plus an active tick before the
  next automatic opening. Fast weapons may therefore attack more slowly in a crowd.
- **Impact priority:** an automatic opening is deferred if a predicted projectile
  or explosion is within seven ticks (opening plus shield startup). Manual attack
  presses can override this, at the cost of exposure. This is prediction, not a
  guarantee: unexpected/new threats, latency and server rules can still cause damage.
- **Your item use wins:** physically holding Use, eating, charging a bow and manually
  held shields are not forcibly cancelled. Airborne mace-smash/launch handoffs from
  previous releases are preserved. Disabling the module, opening a menu, losing
  focus, changing world or losing authorization clears pending openings.

**React to Swings** (page 4/5) notices a newly observed, nearby, visible, front-facing
swing animation and requests a short guard pulse. It does not predict exactly when
damage arrives or bypass shield startup. Close Melee Guard (page 5/5) is the broader
proactive proximity guard; both can coexist, but neither promises perfect blocking.

Auto Shield still works independently with all auto-attack/aim modules OFF. Turning
attack windows OFF restores continuous defense behavior where threats persist.

## In-game acceptance checklist

Use a disposable survival arena and ordinary sword first; avoid relying on automation
to protect valuable inventory during testing.

1. Auto Shield ON, offhand shield, Close Melee Guard ON; all attack/aim modules OFF.
   Face a nearby zombie until blocking, then click Attack: one vanilla attack should
   be possible and the shield should return if danger remains. No unsolicited hits.
2. Repeat with Attack remapped to another mouse button and then a keyboard key.
   Hold Attack: it must not repeatedly flicker the shield. Press it again for another
   manual opening. Check mining during a manual opening, too.
3. Enable Cooldown Attack, face an eligible mob and wait without clicking. Verify
   full-charge hits, a brief drop per hit and blocking between hits, even in a crowd.
   Test sword/axe; after switching slots, no premature hit should occur.
4. Aim at empty air, a wall, a teammate or a neutral player: no automatic gap just
   to attack them. Test target loss during an opening; shield must not stay stuck down.
5. Add a facing skeleton/visible fuse threat: automatic openings should defer near
   the predicted impact. Manual attacks still override. Check actual damage/block
   feedback, not merely whether the shield graphic is raised.
6. Hold Use to build, eat, draw a bow or block manually: automatic attack windows
   must not hijack it. Retest wind-charge-to-mace and Wind Burst resets separately.
7. Disable Shield Attack Windows: continuous close-guard behavior should return.
   Toggle Auto Shield OFF, use emergency disable, change world, open menus and lose
   focus: no stuck synthetic Use key or delayed auto-attack should remain.

## Verification boundary

Regression tests cover window expiry, manual priority, full-charge cadence, duplicate
prevention, reblock recovery, impact margins, crowd starvation and saved opt-out.
Compilation and package checks do not replace live tests of input ordering, block
rates, high-latency play, render performance or third-party mod interactions.
